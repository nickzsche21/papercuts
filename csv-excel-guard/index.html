Why does Excel destroy CSV files?

Excel doesn't ask what your data is. When it opens a .csv it guesses a type for every cell, then rewrites the cell to match its guess — and once you save, the original value is gone. There is no warning and no undo.

This is not a rare edge case. In 2020 the HUGO Gene Nomenclature Committee formally renamed human genes because Excel kept converting SEPT1 into 1-Sep and researchers were publishing corrupted datasets. On Stack Overflow, “Stop Excel from automatically converting certain text values to dates” has over 669,000 views, and the leading-zero and scientific-notation variants add hundreds of thousands more.

What this tool checks for

  • Date coercion — SEPT1 → 1-Sep, 3/4 → 4-Mar
  • Ambiguous dates — 03/04/2026 means March in the US and April in the EU
  • Leading zeros stripped — ZIP 02134 → 2134
  • Scientific notation — a 13-digit barcode → 1.23457E+12
  • Precision loss — Excel keeps only 15 significant digits, so a 19-digit ID is silently rounded and cannot be recovered
  • Formula injection — a cell starting with =, +, @ is executed, which is both a data bug and a real security vulnerability (CWE-1236)
  • International phone numbers — +44 20 7946 0958 becomes #NAME?
  • Missing UTF-8 BOM — the reason accented names arrive as Ã©
  • Invisible characters, ragged rows, duplicate headers

Does my file get uploaded?

No. Every check runs in your browser with JavaScript. There is no server, no upload, and no request of any kind — you can open your network tab and watch nothing happen, or disconnect from the internet and it still works.

What do the two downloads do?

Excel-safe CSV wraps every flagged cell as ="value" and adds a UTF-8 BOM. Excel will display the exact original text. Use this when a human will open the file in Excel.

Sanitised CSV adds the BOM, strips invisible characters, trims stray whitespace, and neutralises formula-injection cells with a leading apostrophe. Use this when a script or database will read the file.
