Why isn't my .gitignore working?

Paste your rules and your paths. See which single line decides each file, catch the re-include that silently does nothing, and find out whether the real answer is that git is already tracking the file.

Tip: git ls-files pastes straight into the right-hand box and shows you what git is actually tracking today.

The four reasons .gitignore "doesn't work"

1. The file is already tracked — this is nearly always it

.gitignore only applies to files git is not already tracking. Once a file has been committed, git keeps tracking it forever and no pattern will change that. You have to remove it from the index first, which is what git rm --cached does — it untracks the file while leaving it on disk. The Stack Overflow question for this alone has over 100,000 views, and the answer is never "fix your pattern".

2. A parent directory is excluded, so the re-include never runs

This one is genuinely counter-intuitive. If you ignore build/ and then write !build/keep.txt, the exception does nothing. Git does not descend into an excluded directory, so it never sees the file to re-include it. The fix is to exclude the contents rather than the directory: build/* followed by !build/keep.txt. This tool flags the trap wherever it finds it.

3. The last matching line wins, not the most specific

Ordering is everything. A broad *.log placed after !important.log silently re-ignores the file you were trying to keep. The result below names the exact line number that made the final decision, so you can see which rule is overriding which.

4. The pattern is anchored differently than you think

A pattern containing a slash anywhere except at the end is anchored to the location of the .gitignore. So doc/build matches only at the top level, while a bare build matches a directory called build at any depth. Adding or removing one slash changes which files are affected.

Does this run real git?

No — it reimplements git's matching rules in the browser: negation, directory-only patterns, anchoring, character classes, **, last-match-wins precedence, and the rule that an excluded directory is never descended into. Nothing is uploaded and no repository is read.
