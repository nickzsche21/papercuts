Why the same regex behaves differently everywhere

"Regular expression" stopped being one thing decades ago. Every engine added its own extensions, and two of the most popular ones deliberately removed features. A pattern that passes in your editor can be a syntax error in production.

Go and Rust genuinely cannot do lookaround or backreferences

This is not an oversight. Both use RE2-style engines that guarantee matching in time linear to the input, which makes them immune to catastrophic backtracking. Lookaround and backreferences are exactly the features that make that guarantee impossible, so they are not implemented and never will be. There is no flag and no workaround — if you need them, you have to match more loosely and filter the results in code.

Lookbehind is supported in more places than it is supported well

JavaScript and .NET allow variable-length lookbehind. Python's re requires a fixed width and raises an error otherwise. Java allows bounded lengths only. PCRE historically required fixed width and offers \K as an escape hatch. So (?<=ab|abc) is fine in one engine and an error in the next, which is why the Stack Overflow question about lookahead, lookbehind and atomic groups has over 679,000 views.

Named groups have three incompatible syntaxes

Python's re wants (?P<name>…). JavaScript, Java and .NET want (?<name>…). PCRE accepts both plus (?'name'…). Copying a pattern between languages fails on this alone, so this tool rewrites it for you.

Is my pattern executed?

No. The pattern is scanned for the constructs it uses — it is never compiled or run against anything, so a pattern with catastrophic backtracking cannot hang this page. Nothing is uploaded either; the whole check runs in this tab.

How current is the compatibility data?

It reflects current stable releases, and version-sensitive entries are labelled where it matters — notably Python gained atomic groups and possessive quantifiers in 3.11, and JavaScript gained lookbehind in ES2018. When a feature is marked partial, hover or read the note for the specific restriction.
