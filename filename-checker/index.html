Will this filename break?

Checks every name against Windows, macOS, Linux, SharePoint / OneDrive, S3 and Git — reserved words, illegal characters, path limits, and the case and Unicode collisions that only appear on someone else's machine.

Choosing a folder reads only the names. No file contents are opened, and nothing is uploaded.

Why filenames break

Every operating system and every sync tool has a different idea of what a legal filename is, and you only find out at the worst moment: the upload fails, the ZIP won't extract, the repo won't check out on a colleague's laptop, or SharePoint silently refuses half a folder.

The classics

  • Reserved device names. On Windows, CON, PRN, AUX, NUL, COM1–COM9 and LPT1–LPT9 cannot be filenames — with any extension. con.txt is still illegal.
  • Illegal characters. Windows rejects < > : " / \ | ? *. A colon is the single most common offender, because it looks fine on macOS.
  • Trailing dots and spaces. Windows silently strips them, so report. and report become the same file.
  • Case collisions. README.md and readme.md are two files on Linux and one file on macOS and Windows. This is how a Git repo becomes impossible to check out.
  • Unicode normalisation. macOS stores é decomposed (NFD), Linux stores whatever you typed. The same visible name can be two different files — or collide unexpectedly.
  • Length. Linux caps a single name at 255 bytes, so an emoji costs four. Windows caps the whole path at 260 characters by default. SharePoint caps the full URL at 400.

What are the safe replacements?

For each broken name the tool proposes a version that is legal everywhere: illegal characters replaced, reserved names suffixed, trailing dots and spaces trimmed, invisible characters removed, and length brought under the limits with the extension preserved. You can copy the whole set as a mv script.

Is anything uploaded?

No. Reading a folder gives the browser a list of names; this page never opens the files and never makes a network request.
