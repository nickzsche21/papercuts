Nested JSON, flattened properly

API responses nest four levels deep and every converter gives you [object Object]. This one flattens the whole tree, lets you decide what happens to arrays, and hands you a CSV that opens.

Why flattening nested JSON is annoying

A spreadsheet is a rectangle. JSON is a tree. Every conversion has to make a decision the format itself cannot express, and most tools make the decision badly — silently stringifying an object into [object Object], or dropping nested arrays entirely.

“How to flatten multilevel/nested JSON?” has over 175,000 views on Stack Overflow, and the nested-JSON-to-CSV variants add tens of thousands more. Everyone hits it; nobody enjoys it.

The three things that can happen to an array

Join keeps one row per record and squashes ["red","blue"] into a single cell reading red; blue. Best when the array is a tag list you just want to eyeball.

Index gives each element its own column: tags.0, tags.1, tags.2. Best when the array has a small, fixed length.

Explode gives each element its own row, repeating the parent fields — a real unnest. An order with three line items becomes three rows. This is almost always what you want for analysis, and it is the one most converters do not offer.

Does it handle NDJSON?

Yes. If the text is not valid JSON as a whole, each non-empty line is parsed separately, so newline-delimited logs and BigQuery or Mongo exports work as-is.

Does my data get uploaded?

No. Parsing, flattening and CSV generation all happen in this tab. There is no server and no network request.

Will the CSV open cleanly in Excel?

The download includes a UTF-8 byte-order mark so accented characters survive. If the data contains IDs, ZIP codes or barcodes, run the result through Will Excel break my CSV? — Excel will happily turn a long order ID into 1.23457E+12 without telling you.
